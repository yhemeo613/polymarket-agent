# polymarket-agent 开发计划与进度文档

> 全自主 AI 预测市场 Agent（Polymarket）· NestJS + TypeScript · 无 UI（仅 ops API）
> 架构依据：`../全自主AI预测Agent_黑盒实验研究方案.md`
> 原则：**LLM 研究、代码管钱；paper-first；一切可审计；统计纪律内置**

---

## 一、技术栈与三方库

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | NestJS 11 + TypeScript 5.x | 模块化 DI，@nestjs/config / @nestjs/schedule / nestjs-pino |
| 数据库 | better-sqlite3 + drizzle-orm | SQLite 单文件，phil 已验证足够；建表用原生 SQL（IF NOT EXISTS），查询用 drizzle 类型安全 |
| Polymarket 执行 | @polymarket/clob-client（官方 v5.x）+ viem | EIP-712 签名、订单构建、GTC/postOnly |
| 行情 | axios（Gamma/CLOB REST）+ ws（市场 WS 增量，可关闭） | REST 轮询为主，WS 可选 |
| LLM | @anthropic-ai/sdk + zod 结构化输出 | 无 key 时自动切换 BaselineProvider（p̂=市场价，即 H0 基线），全链路照常运行 |
| 数值 | decimal.js | edge/费率/Kelly 全部 Decimal，禁止浮点直接算钱 |
| 日志审计 | pino（nestjs-pino）+ SHA-256 hash 链账本 | 结构化日志 + 防篡改决策账本 |
| 告警 | Telegram Bot API（axios 实现，可选） | 无配置则降级 console |
| 测试 | jest + ts-jest | 不变量测试（费率数学/edge/Kelly/风控/评分/撮合） |
| 时间 | dayjs | — |

## 二、架构总览

```
┌──────────── L5 进化层 evolution ─────────────────────────────┐
│ Settle→Score(brier_delta/luck-z)→Retro(LLM三问)→策略编辑→影子晋升 │
│ 策略=strategy/ 目录(playbook.md LLM可编辑 / params.json 人工)     │
└──────────────────────────┬───────────────────────────────────┘
                           ↓
┌──────────── L1 研究层 research(LLM 领地,开卷) ────────────────┐
│ Gamma扫描→硬过滤→LLM语义筛选→证据检索(News/Tavily,可降级)        │
│ →superforecaster五步→{p̂,置信度,证据}→forecast journal(含未下注) │
└──────────────────────────┬───────────────────────────────────┘
                           ↓ 结构化JSON(zod)
┌──────────── L2 决策层 decision(确定性,钱的领地) ───────────────┐
│ 校准:p=σ(a·logit(p̂)+b)向恒等正则 → 影子/在册规则修正 →           │
│ edge=p−ask−fee(p)−slip > min_edge → quarter Kelly 仓位          │
└──────────────────────────┬───────────────────────────────────┘
                           ↓ TradeIntent
┌──────────── L4 风控层 risk(单一入口,paper/live共用) ───────────┐
│ killswitch哨兵→熔断(日亏5%/回撤20%)→单笔2%→单市场5%→总敞口50%     │
│ →持仓≤20→regime 4档乘数 → 全过才放行,拒绝记录原因                 │
└──────────────────────────┬───────────────────────────────────┘
                           ↓
┌──────────── L3 执行层 execution(确定性) ──────────────────────┐
│ PaperBroker:真实盘口深度走单撮合+taker费(默认)                   │
│ LiveBroker:clob-client GTC/postOnly,PAPER_ONLY=false+私钥才初始化│
│ 订单日志幂等(request_id) + 孪生单钩子(未来P2)                    │
└──────────────────────────────────────────────────────────────┘
横向：L0 行情(polymarket模块) · L6 审计(ledger hash链+pino) · 告警(Telegram)
调度：@nestjs/schedule — 主循环(小时cron) / 轻触发(15min持仓监控) / ops API
```

### M11 decision 模块
- 文件：`src/decision/calibration.service.ts` `src/decision/rules.service.ts` `src/decision/edge.calculator.ts` `src/decision/kelly.sizer.ts` `src/decision/decision.service.ts` `src/decision/decision.module.ts`
- 要点：校准 `p=σ(a·logit(p̂)+b)`（n≥50 才拟合，L2 向恒等 (1,0) 正则，牛顿法确定性）；规则引擎（在册 ACTIVE + 影子 SHADOW 纯函数规则，p_final 经在册规则，影子规则仅记录不生效）；edge（Decimal：p_final − bestAsk − takerFee − slippageEst）；`f*=(p̂−p)/(1−p)` quarter Kelly + 2% 单笔帽；输出 TradeIntent 或 null+skip_reason
- 验收：不变量测试（edge 数学、Kelly 数学、校准恒等性）

### M12 risk 模块
- 文件：`src/risk/kill-switch.service.ts` `src/risk/regime.service.ts` `src/risk/risk.engine.ts` `src/risk/risk.module.ts`
- 要点：kill switch = `data/kill.switch` 哨兵文件（进程外可 touch；每次校验读两次：await I/O 后二次复查防竞态）；regime 由 24h 波动代理分 4 档（calm/normal/elevated/extreme，extreme 直接停机），仓位乘数 1.2/1.0/0.5/0.25；RiskEngine.validate(intent) 顺序闸门：killswitch→熔断（日亏>5% 转 paper-only、峰值回撤>20% 全停）→单笔≤2%→单市场≤5%→总敞口≤50%→持仓≤20→regime 调整 size（取 min(请求, Kelly建议)）；每次裁决写 ledger
- 验收：不变量测试（各帽触发路径、哨兵文件生效）

### M13 execution 模块
- 文件：`src/execution/broker.interface.ts` `src/execution/paper.broker.ts` `src/execution/live.broker.ts` `src/execution/order.journal.ts` `src/execution/execution.module.ts`

## 四、运行模式

| 模式 | 条件 | 行为 |
|---|---|---|
| **baseline（默认可跑）** | 无 ANTHROPIC_API_KEY | LLM 层全部返回市场价/直通，H0 基线全链路运行，用于验证管线与采集校准数据 |
| **research** | 配置 ANTHROPIC_API_KEY | superforecaster 开卷预测 + 语义筛选 + 复盘编辑 |
| **paper（默认）** | PAPER_ONLY=true | PaperBroker 真实盘口模拟成交 |
| **live（守卫）** | PAPER_ONLY=false + WALLET_PRIVATE_KEY | LiveBroker 实盘，仍受全量风控闸门 |
| **孪生单** | TWIN_ORDERS=true + live 可用 | 每笔 paper 信号同步 $1 真实单，度量 paper↔实盘成交偏差 |

## 五、实验协议对应（详见研究文档第五章）

- P0 回测 / P1 影子纸面 / P2 小额实盘（孪生单）/ P3 裁决
- 晋升统计门槛：n≥20（影子规则）、brier_delta 配对 99.5% 区间、Bonferroni 由人工评审执行
- 防自欺：占位书剔除、点时数据（journal 落库时快照）、无随机数撮合、幸运 z 监控
